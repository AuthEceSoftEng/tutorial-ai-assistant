## Slide 3: Phase 1: The CLI Chatbot (`main1.py`)
*   **Core Question**: How do LLMs maintain conversations?
*   **Stateless by Design**: LLM API endpoints do not remember previous interactions. Memory is a client-side construct.
*   **Message Schema**: 
    *   `SystemMessage`: Steers the model's behavior, tone, and system boundaries.
    *   `HumanMessage`: Represents user input.
    *   `AIMessage`: Represents the model's generated response.
*   **The Execution**: We maintain a growing list `messages = [system_prompt]`. On every input, we append `HumanMessage`, execute `aimodel.invoke(messages)`, and append the resulting `AIMessage`.

---

## Slide 4: Phase 2: CLI with Streaming (`main2.py`)
*   **The UX Bottleneck**: Waiting for a model to generate a 300-word answer takes 10+ seconds, causing high user drop-off.
*   **The Paradigm Shift**: Replacing blocking invocations with asynchronous generators.
*   **How it Works**: 
    *   Instead of waiting for the entire response, the server yields tokens (chunks) as they are generated.
    *   We replace `aimodel.invoke(messages)` with `aimodel.stream(messages)`.
    *   We iterate over incoming chunks and output them immediately: `print(chunk.content, end="", flush=True)`.
*   **Outcome**: Perception of latency drops from seconds to milliseconds!

## Slide 5: Model Context Protocol (MCP)
*   **The Integration Dilemma**: Before MCP, connecting 5 AI apps to 10 APIs required 50 custom integrations, unique auth tokens, and broke when APIs updated.
*   **The "USB-C for AI"**: Created by Anthropic in late 2024, MCP is an open standard establishing a standard client-server protocol.
*   **How it Works**:
    *   **MCP Server**: Exposes resources (data) and tools (python execution blocks).
    *   **JSON Schema Generation**: Autogenerated from standard Python code. Parameter type annotations and docstrings serve as the documentation the LLM parses.
    *   **Dynamic Discovery**: At runtime, the client queries the server, dynamically discovers available schemas, and binds them to the model.

## Slide 6: Phase 3: Bypassing Streamlit for Chainlit (`main3_chainlit.py`)
*   **Why Skip Streamlit?**: Streamlit is an excellent data dashboard library, but handles conversational systems poorly. It lacks native async streaming support, forces complex page-reload logic, and requires verbose session state hacks.
*   **Chainlit Advantage**: A dedicated, ultra-modern conversational UI library built specifically for AI agents.
*   **The Async Lifecycle**:
    *   `@cl.on_chat_start`: Triggers when the user opens the web page. Used to initialize system prompts and set up session-level storage.
    *   `@cl.on_message`: Handles incoming prompts. Operates inside fully asynchronous callbacks.
    *   `cl.user_session`: Simple, safe dictionary-based memory caching per active user session.

## Slide 7: Phase 4: Exposing Local Tools via MCP (`mcpserver.py`)
*   **The Challenge**: Exposing lightweight local python execution blocks as API endpoints standardizing AI integration.
*   **The Baseline Tools**:
    1.  `add_numbers(a, b)`: Simple utility providing clean mathematical arithmetic feedback.
    2.  `get_time()`: Direct access to local system date, time, and active timezone coordinates.
*   **Modular Example Servers**:
    *   `mcp_simple.py`: Baseline math and system clock server.
    *   `mcp_weather.py`: REST-based Geocoding & live open-meteo weather server.

    *   `mcp_advanced.py`: Reference developer tools (DuckDuckGo search, AST linters, Git controller).
*   **Colab Interactive Sandbox**: Students edit, add, or remove tools inside their notebook directly to compile and launch `mcpserver.py` on Port 8001!

## Slide 8: The Mechanics of the Agentic Loop
*   **Linear Chains vs. Agent Cycles**: Standard LLM pipelines flow straight from input to output. Agents require a feedback cycle:
```
           ┌──────────────────────────────────────────────┐
           ▼                                              │
   User Prompt ──► LLM ──► [Tool Requested?] ──► Exec Python Tool
                             │
                             └───► [No Tool] ──► Final Explanation
```
*   **The Interception Protocol**:
    1.  LLM responds with a list of `tool_calls` containing JSON arguments.
    2.  The Python client intercepts this list and halts verbal output.
    3.  The client executes the tools, packages outcomes into `ToolMessage` instances, and appends them to message history.
    4.  LLM is re-invoked with the tool results as grounded facts to form the final answer.

## Slide 9: Phase 5: Building a Resilient Parallel Agent (`main4_agent_chainlit.py`)
*   **Culmination**: Combining parallel speeds, error resilience, and visual traces.
*   **Offensive Speed - Parallel Execution**:
    *   Sequential execution slows down agents. We implement **`asyncio.gather()`** to fire all requested tool calls concurrently.
*   **Defensive Resilience - Self-Correction**:
    *   If a tool fails (e.g. invalid URL), we wrap the call in a `try-except` block and feed the exception traceback back to the LLM in a `ToolMessage`. The LLM reads the error and self-corrects without crashing.
*   **Chainlit UI - Collapsible Traces**:
    *   Chainlit's native `cl.Step` nests tool executions beautifully under collapsible bubbles, showing arguments and outputs dynamically.
